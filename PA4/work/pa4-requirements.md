# PA4 requirements extracted from the official brief

Source: `PA4\PA4-LKDuy-2026-Public.pdf`, read on 2026-08-23.

## Hi-fi prototype

- Choose the best PA3 lo-fi version and develop it using formative-testing results.
- Rich fidelity: detailed color, UI elements, and animations where useful.
- Realistic touch, mouse, and keyboard interactions.
- Real or similar-to-real content that makes sense for the chosen context.
- Prototype must be complete before the demo/presentation.

## Summative user study

Before testing:

- Detailed setup, procedure, questionnaires, and study design.
- Invite at least five participants.
- Define team-member tasks.
- Define evaluation measures.

During testing:

- Video-record all testing sessions.

After testing:

- Gather participant feedback through interviews.
- Collect questionnaire answers and insights.
- Collect other measurements such as task completion time and compare with current practice when valid.

## Demo

- Present the final product in a 15–20 minute session.

## Weekly report

- Track each team member’s tasks with the provided course template.

## Required submission filenames

- `Group10-PA4-HifiProtype.pdf` — page 1 must include YouTube demo video links.
- `Group10-PA4-SummativeUserStudy.pdf`.
- `Group10-PA4-WeeklyReport.pdf`.
- Package: `Group10-PA4.zip`.

## Evidence gate

The brief requires real participants and recorded sessions, but none existed in the local PA4 state at audit time. The implementation therefore includes the complete collection and analysis mechanism while marking outcome evidence `BLOCKED EXTERNALLY`; it does not fabricate results.
