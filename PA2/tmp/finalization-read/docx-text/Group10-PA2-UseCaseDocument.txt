5. FIFA use case specifications
F-UC01 Select tournament or team
Main Success Scenario
1. Actor initiates select tournament or team.
2. System presents the current context, provenance, and primary action.
3. Actor reviews the information and selects the intended option.
4. System validates required input and explains any uncertainty or boundary.
5. Actor confirms the action.
6. System completes the action and preserves a visible next or return path.
Alternative and Exception Flows
A1 at step 3: Actor changes context; system updates the decision surface and preserves prior input when safe.
A2 at step 5: Actor cancels or stays; system returns to step 2 without external side effects.
E1 at step 2: Required data is unavailable or stale; system labels the limitation, shows last-known provenance, and offers retry or safe exit.
E2 at step 4: Input is invalid or inaccessible; system focuses the error summary and returns to the exact field.
E3 at step 6: External service fails; system preserves the local context and provides a return/retry path.
